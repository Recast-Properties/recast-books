## The method worked out for the open task (nothing started)

**Facts to build on**
- A Journal line is linked by its `doc_url`. Today every Molalla line carries his sheet's link. `setDocUrl_(txnIds,
  url, props)` (Code.gs) fills `doc_url` on the Journal lines of given txn ids - reuse it.
- **A frozen tab's Receipt column is plain text.** `freezePropertyTab_` does `setValues(getValues())`, which turns
  each `=HYPERLINK(...)` into the word "Receipt" with no link (by the code - look at the live cell first; Granite's
  and Sparkling's frozen tabs would have the same). So the linking script must itself write `=HYPERLINK(url,
  "Receipt")` into the Receipt cell of each matched row on `1014 S View - Frozen` and blank the cell on a row with
  no receipt. Rows are found by the txn id in the block's last column (the list blocks start at row 6; Rehab Costs
  block then the Utilities block; the 33 purchase-side lines on 1000 are not listed on the tab at all).
- **His sheet is item by item and Oregon has no sales tax:** one store receipt is several lines of the same store
  and date, each amount printed on it, adding to its total. Match on store + date + amounts; a receipt usually
  links to several txn ids.
- **The Drive connector reads receipt photos:** `read_file_content` on `floor and decor reciept.jpg` returned the
  store, 09/22/2025 and 2,533.42 = his line. So once a receipt is a Drive file, a session can read and match it
  without any API cost.
- The entries' ids are deterministic: rebuild them offline from commit `542847e`'s `molallaParse_` /
  `molallaPlan_` and the sheet text (the dry run did exactly this), or read the Journal rows 3222-3546.
