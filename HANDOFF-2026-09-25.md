## Tools / gotchas learned today

- Auto mode denies `git remote add`, any keychain/credential read, and any write to the Blobs store - even
  preparing the JSON for one. Those are Paul's Terminal steps. `scripts/mark-envelope.mjs` exists for envelope
  repair; `recover-errored.mjs` for error replays; both need his login.
- A synchronous `approve` through the API can outlive Netlify's proxy (HTML "Inactivity Timeout") and still
  land - check the Journal before retrying.
- Fire re-reads one at a time, 75 s apart. The writer serialises everything.
- `netlify blobs:get` is `-O` (capital) for the output path.
- The Journal snapshot in `books-cache` is briefly absent right after a post (invalidate, then refresh).

## Part 1 - reads off the writer (the big one, do first)

**Why:** the writer serialises every call through an Apps Script web app that drops replies under load.
Reads are ~95% of its traffic (five per ingest, nine tabs per warm run, whole-Journal each) and writes are a
handful a day. Every 09-25 failure was a read timing out or a write's reply lost behind reads.

**Paul's one setup step (walk him through it, one screen at a time):** in the Google Cloud project that
already holds the site's OAuth client (`GOOGLE_CLIENT_ID`), create a **service account** (no roles), create a
JSON key, then share the workbook **Recast Books** (`12QVyxm3KnLD7CDC8mFAPd5ulZuRXRluNDi4qK4BBxKM`) with the
service account's email as **Viewer**. He then sets two Netlify env vars in the production context
(`netlify env:set --context production`): `SHEETS_SA_KEY` (the key file, base64) and `SPREADSHEET_ID`.
Sheets API must be enabled on that project (one click). No cost.

**Code (no new dependency - ponytail):**
- `lib/sheets-reader.mjs`: RS256 JWT with `node:crypto` -> `oauth2.googleapis.com/token` (scope
  `spreadsheets.readonly`, cache the token ~50 min) -> `GET spreadsheets/{id}/values/{tab}!A:Z` with
  `valueRenderOption=UNFORMATTED_VALUE&dateTimeRenderOption=SERIAL_NUMBER`. Return `{headers, rows}` in
  **exactly** the writer's `readTabData_` shape (`apps-script/writer/Code.gs:651`): numbers as numbers,
  Date cells -> `formatIsoDate_` (yyyy-mm-dd), the timestamp columns (`posted_at`, `void_at`, ...) ->
  `formatIsoTimestamp_`, period columns -> `normalizePeriod_`. Copy the three column lists from Code.gs;
  convert Sheets serial numbers (days since 1899-12-30, spreadsheet timezone America/Chicago) yourself.
- `netlify/functions/_shared.mjs` `fetchTabFromWriter` -> `fetchTab`: use the reader when `SHEETS_SA_KEY` is
  set, else the writer (so production keeps working until the env is in). Nothing else changes: `readTab`,
  `refreshTab`, the `books-cache` snapshots, `applyReadOpts` all stay.
- **Tie-out test before switching:** a script (`scripts/reads-tieout.mjs`, Paul runs it, it needs the key)
  reads every tab both ways and diffs cell by cell. Zero differences on all nine tabs, then flip. Keep the
  writer's `read` action in place - the workbook menu and `clasp` helpers still use it.
- After the flip: `JOURNAL_READ_TIMEOUT_MS` back to 60 s; `MAX_RETRIES_PER_RUN` can go to 5; the warm job's
  `WARM_TABS` refresh becomes cheap - leave the schedule alone.
- Expect the doGet misfire to all but vanish (writes are alone). Keep `confirmPosted` anyway.

## Part 2 - approve in the background (small, do second)

`books-inbox.mjs`'s `approve` verb does Drive filing + postBatch + envelope in a synchronous function that
Netlify's proxy cuts off at ~26 s - it happened twice on 09-25 (Energy Texas, Atmos), both times AFTER the
write landed, leaving the envelope at `posting`. Move the work to `books-approve-background.mjs`
(`/api/approve-bg`, poller secret, same pattern as `books-settlement-background.mjs`): the sync verb
validates, builds entries, marks `posting`, fires the background job, answers 202. The background job files,
posts, writes the envelope, and on a lost reply uses the same Journal confirmation as ingest. The workbook's
in-process `inboxApprove` (Menu.gs) is untouched - it never goes through HTTP. Test with the ingest test's
fake writer.

## Part 3 - the nightly check, done by the brain (do third)

**Why:** on 09-25 the books were checked by hand and it found two duplicate entries and four envelopes that
disagreed with the Journal. That is judgment work and it should happen every night, by the model, before
Paul's digest.

- `netlify/functions/books-reconcile-background.mjs` (`/api/reconcile-bg`, poller secret). **Code gathers
  the facts** from the `books-cache` Journal snapshot and the docs store (both cheap after Part 1):
  (a) posted envelopes whose `result.txn_ids` are not on the Journal; (b) `source = receipt` entries with no
  posted envelope naming their txn_id; (c) non-void entries sharing normalised payee + date + debit total
  (the 09-23 `reportDuplicateReplays` key, live-vs-live AND live-vs-migration); (d) receipt entries with no
  `doc_url`; (e) envelopes in `processing`/`posting` older than an hour, and every `error`; (f) Pending
  count and oldest age; (g) debits = credits, and each held property's tab total vs its Journal sum if cheap.
- **The model judges** (one call, no tools, the same Anthropic client as the bookkeeper, `checked`-style
  output): it gets the table and writes at most eight bullets, each an action in Paul's words ("Void
  receipt-… - twin of migration-…", "Approve Atmos - read is clean, card 9166"), or "Books check: clean."
- Stored at `books-cache` key `reconcile/<yyyy-mm-dd>`; `/api/summary` returns it as `check`; the paul@
  poller's `dailyDigest` prints it as the first section. Trigger: the paul@ poller's daily trigger calls
  `/api/reconcile-bg` at 2:30 AM CT (new trigger in `setup()`), and the digest at 3:00 reads the result.
- Rails on the check itself: it never writes to the workbook; voids and approves stay Paul's clicks.
